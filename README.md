# بوابة مكتب سامح عمار على Firebase

هذه النسخة تستخدم Firebase Authentication لتسجيل الدخول، وCloud Firestore للقضايا والعملاء والمهام، وFirebase Storage للمستندات. لا توجد حسابات عامة؛ أنشئ حساب المكتب يدويًا من Firebase Console. تستخدم الواجهة جلسة تسجيل دخول تنتهي عند إغلاق المتصفح.

تستخدم المنصة شعار ميزان مخصصًا، وتعرض بيانات الحقوق: تطوير المهندس عمرو جمال عوض، والمنصة خاصة بالمحامي سامح عمار ومكتبه.

## الواجهة

تدعم الواجهة العربية واتجاه RTL، مع التبديل بين المظهر الفاتح والداكن من زر الشمس/القمر في شاشة الدخول أو شريط المكتب. يُحفظ اختيار المظهر على الجهاز، ويُستخدم إعداد النظام عند عدم وجود اختيار محفوظ. تعتمد الخطوط على خطوط النظام العربية لتعمل الواجهة دون تحميل خط خارجي.

يظهر تنبيه أمان مختصر على شاشة تسجيل الدخول: لا تشارك كلمة المرور أو رموز التحقق. وضع الدخول التجريبي المحلي غير آمن؛ لا تستخدمه مع بيانات عملاء حقيقية.

من القائمة بعد تسجيل الدخول تتوفر صفحة تقويم شهري للجلسات مع قائمة مواعيد اليوم، وبحث شامل في القضايا والعملاء وبيانات التواصل وأسماء مستندات العملاء (اختصار لوحة المفاتيح Ctrl+K)، وتقارير إحصائية للقضايا قابلة للطباعة أو التصدير بصيغة CSV. ملفات CSV والتقارير قد تحتوي بيانات سرية، فاحفظها في مكان آمن.

يمكن إرفاق عدة مستندات من نموذج إضافة أو تعديل القضية، واختيار تصنيف مستقل لكل ملف (مثل مستند قضائي أو توكيل أو عقد) قبل الرفع. تُحفظ الملفات المسموحة (PDF وWord والصور وTXT، حتى 10 ميجابايت لكل ملف) ضمن مستندات ملف العميل المرتبط بالقضية، ويظهر التصنيف في الملف ويمكن البحث عنه. تم تكبير أحجام النصوص الأساسية في الواجهة واستخدام خطوط نظام مناسبة للعربية لتكون القراءة أوضح دون الحاجة لاتصال خارجي.

### إدارة القضية والأتعاب والمستندات

- افتح «السجل» بجوار أي قضية لإضافة محاضر المتابعة والقرارات والخطوة التالية. تحفظ المتابعة في الخط الزمني، وتُنشأ مهمة مرتبطة بالقضية؛ ويمكن تسجيل موعد الجلسة التالية لتعمل عليه تذكيرات الجلسات الحالية.
- من «الأتعاب والمصروفات» سجّل الأتعاب المتفق عليها والدفعات ومصروفات القضية، مع إيصال اختياري محفوظ في ملف العميل. تعرض الصفحة إجماليات الحركات؛ المتبقي هو الأتعاب المتفق عليها ناقص الدفعات. هذه أداة متابعة وليست نظام محاسبة أو فواتير ضريبية.
- قوالب المكتب تنشئ مسودات متابعة جلسة أو إخطار أو مذكرة داخلية مرتبطة بالقضية. يمكن تنزيلها بصيغة Word المتوافقة، أو طباعتها واختيار «حفظ PDF». راجع وحرر كل مسودة وفق وقائع القضية والقانون المختص قبل استعمالها.
- «بحث بالمستندات» يستخرج النص من TXT وPDF النصية وDOCX على جهاز المستخدم، ولا يرفع المحتوى إلى خدمة بحث. لا يتضمن OCR، ولذلك لا يبحث داخل الصور أو PDF الممسوحة ضوئيًا أو ملفات DOC القديمة. تُحتفظ نتائج النص في ذاكرة الجلسة فقط وتمسح عند تسجيل الخروج؛ تُحمّل مكتبة قراءة PDF من cdnjs عند الحاجة.

## تثبيت الموقع على الهاتف

بعد نشر الموقع على Firebase Hosting أو استضافته على عنوان HTTPS، يمكن تثبيته كتطبيق ويب:

- **Android / Chrome:** افتح الموقع، ثم استخدم زر «تثبيت التطبيق» إذا ظهر، أو قائمة Chrome ثم «تثبيت التطبيق» / «إضافة إلى الشاشة الرئيسية».
- **iPhone / iPad:** افتح الموقع في Safari، واضغط زر «مشاركة» ثم «إضافة إلى الشاشة الرئيسية». يظهر الإرشاد داخل شاشة الدخول، ويمكن استخدام زر التثبيت في شريط المكتب لعرضه مجددًا.

يعمل التثبيت على عنوان HTTPS أو localhost فقط؛ فتح `index.html` مباشرة كملف لا يتيح تثبيت الموقع. تظهر خيارات التثبيت بحسب دعم المتصفح وحالة تثبيت التطبيق. يستخدم الموقع عامل الخدمة الموجود لتنبيهات Firebase عند تفعيلها، ولا يخزّن بيانات القضايا أو ملفات العملاء دون اتصال.

## إعداد Firebase

1. إعداد Web app لمشروع `samehamar` موجود بالفعل في `firebase-config.js`، والمشروع الافتراضي محدد في `.firebaserc`. إعدادات Web API ليست كلمات مرور، ولا تضع مفاتيح Service Account أو Admin SDK في ملفات الموقع.
2. من Authentication، فعّل Email/Password وأنشئ حساب المكتب بنفسك. لا تضف واجهة إنشاء حساب. من Authentication → Settings → Authorized domains، أضف `localhost` للاختبار المحلي و`samehamar.web.app` للنشر إذا لم يظهرا تلقائيًا. فعّل التحقق بخطوتين للحساب إن كان متاحًا في إعداد مشروعك.
3. أنشئ Cloud Firestore وحدد منطقة البيانات بعناية قبل الإنشاء؛ لا يمكن تغيير موقع قاعدة البيانات بعد إنشائها. راجع متطلبات سرية بيانات العملاء ومكان استضافتها قبل الاختيار. أنشئ Firebase Storage وفعّل Firebase Cloud Messaging. الإشعارات تحتاج مفتاح Web Push/VAPID مستقلًا؛ لا تفعّلها قبل وضعه في `firebase-config.js`.
4. ثبّت Node.js 22 وFirebase CLI، ثم من PowerShell في مجلد المشروع شغّل:

   ```powershell
   npm install
   npx firebase login
   npm run deploy
   ```

   يستخدم Firebase CLI المشروع `samehamar` المحدد في `.firebaserc`. راجع القواعد المنشورة قبل إدخال مستندات حقيقية.
5. خدمة التذكيرات المجدولة اختيارية؛ لنشرها فقط، ثبّت تبعياتها باستخدام `npm install --prefix functions` ثم شغّل `npm run deploy:functions`. تحتاج Cloud Functions وCloud Scheduler، وقد تتطلب خطة Firebase المدفوعة (Blaze) ووسيلة دفع. المنطقة الزمنية الافتراضية `Africa/Cairo`. إذا احتجت تغييرها، أنشئ `functions/.env.<PROJECT_ID>` اعتمادًا على `functions/.env.example` قبل النشر. يعمل مجدول Functions في `europe-west1`.
6. تنزيل المستندات يتم بمصادقة Firebase. بعد إنشاء Storage bucket، حدّث أسماء النطاقات في `storage.cors.json` ثم أضف إعداد CORS إلى bucket بواسطة Google Cloud CLI:

   ```powershell
   gcloud storage buckets update gs://samehamar.firebasestorage.app --cors-file=storage.cors.json
   ```

7. سجّل الدخول من المتصفح، ثم اضغط «تفعيل التنبيهات» واسمح بإشعارات المتصفح. ترسل Cloud Function تذكيرًا عامًا قبل الجلسة أو مهمة المتابعة بيوم وقبلها بساعة؛ تفاصيل القضية والمهمة لا تظهر في الإشعار. يلزم نشر قواعد Firestore المحدثة التي تحمي مجموعتي `caseEvents` و`financialTransactions` بحساب المكتب نفسه، ثم نشر Functions وHosting.

## التشغيل المحلي

لا يوجد دخول تجريبي أو تخزين محلي بديل؛ يلزم إعداد Firebase صالح وتسجيل الدخول بحساب المكتب في Firebase Authentication على كل من localhost والاستضافة. يلزم تفعيل Authentication وتهيئة Firestore وStorage ونشر القواعد قبل تشغيل بيانات المكتب.

للاختبار قبل النشر، استخدم Firebase Emulator أو مشروع Firebase منفصلًا عن بيانات المكتب الفعلية، مع إعداد محلي لا يُرفع إلى الاستضافة.

## البيانات القديمة

عند أول دخول على العنوان نفسه، تنقل الصفحة سجلات المكتب والمستندات القديمة من التخزين المحلي للمتصفح إلى Firestore وStorage. إذا كنت تستخدم النسخة كملف `file://` وتنتقل إلى Firebase Hosting، نزّل نسخة البيانات من شاشة الدخول قبل الانتقال؛ المتصفح يعزل التخزين المحلي بين العنوانين. بعد الدخول إلى الموقع المستضاف، استخدم «استيراد نسخة قديمة». ملف النسخة الاحتياطية غير مشفّر ويحتوي مستندات سرية: احفظه مؤقتًا في مكان مشفّر واحذفه بعد التحقق من اكتمال الاستيراد.

## حدود الأمان

قواعد Firestore وStorage تقصر القراءة والكتابة على حساب Firebase صاحب المعرّف نفسه. استخدم كلمة مرور فريدة طويلة، ولا تنشئ حسابات إضافية إلا لمن يحتاج الوصول. فعّل MFA، واختبر قواعد Firebase قبل إضافة ملفات العملاء. البيانات مخزنة في مشروع Firebase؛ لا تتضمن هذه النسخة تشفيرًا من طرف إلى طرف، أو نسخًا احتياطيًا تلقائيًا، أو مشاركة آمنة للملفات.
